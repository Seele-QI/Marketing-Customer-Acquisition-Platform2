一次任务如何运行
1. 接收用户选角色或交给纪衡；附件进入任务临时区。
→
2. 预检鉴权、文件签名/大小、敏感信息、积分预算。
→
3. 分诊确定主责、会签、所需 Skill、知识域和工具。
→
4. 锁定保存角色/Skill/模型路由版本快照，保证可复盘。
→
5. 执行主责智能体工作；会签只收到最小必要上下文。
→
6. 审批T2 动作暂停，展示对象、内容、成本与影响。
→
7. 交付汇总结论、分歧、来源、状态和未完成事项。
模型对用户隐身云端下发候选模型与策略；任务开始时保存实际模型快照。
任务预算封顶限制模型调用数、会签数和工具费用；超预算前停止并说明。
失败不伪装单部门失败可输出 partial；外部动作必须有结果证明才算成功。
审批可恢复审批记录绑定参数哈希与版本；内容变化后必须重新审批。
三阶段交付边界

阶段 1 · 可用团队

  • 14 角色与原创头像
  • Agent Runtime 与自动模型路由
  • 图片/文件临时附件
  • Skill 目录与主责/会签
  • 引用、风险、预算与基础审计

阶段 2 · 企业知识与审批

  • 三层知识库与部门 ACL
  • 安全解析、入库审核与版本
  • 统一审批中心和恢复执行
  • 角色与 Skill 评测后台

阶段 3 · 外部执行

  • 邮件、日历、CRM 等连接器
  • 各平台发布与结果回传
  • 逐渠道真实账号 UAT
  • 仅验证通过后标记可用
