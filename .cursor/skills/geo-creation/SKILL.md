# GEO 创作技能

> 生成式引擎优化（GEO）内容创作与结构化输出规范。蒸馏自项目 `GEO/README.zh.md`。

## 何时触发

当用户提及以下任一主题时启用本技能：

- GEO、生成式引擎优化、Generative Engine Optimization
- AI 可见度、AI 搜索、引用份额、提示词覆盖
- Schema 标记、JSON-LD、FAQPage、实体建模
- ChatGPT / Claude / Gemini / Perplexity 品牌提及与引用监测
- 对话式内容、证据驱动写作、主题集群

## 四步工作流

对齐 AgentHub GEO 优化栏目的四个子页面：

### 1. 知识库（企业知识库搭建）

- 建立品牌/产品/FAQ **实体模型**
- 输出 Organization、Product、FAQPage 的 **JSON-LD 清单**
- 校验：Schema 完整性、实体命名一致性、权威链接（sameAs）

### 2. 矩阵（内容矩阵规划）

- **必读子技能**：`skills/geo/creation-guidelines/content-matrix-planning/SKILL.md`（两周跨平台矩阵准则）
- 规划 **两周 Sprint 内容矩阵**（14 格/平台，跨平台 `themeArc` 关联）
- 多选 **8 平台**（小红书/抖音/知乎/微博/大众点评/携程/网易/搜狐），平台原生差异化改写
- 可选 **A 层模型权重 + C 层企业知识库** 参与 AI 一键生成；服务端多项目存储（登录用户隔离）

### 3. 创作（深度优化文章创作）

- **必读子技能**：`skills/geo/creation-guidelines/deep-article-optimization/SKILL.md`（深度优化文章创作准则）
- **硬规则**：先多平台检索（知乎/贴吧/小红书/热搜）再动笔；拒绝洗稿与无出处数据
- **语义清晰度**：H2 结构、概念定义、上下文线索
- **对话式设计**：第二人称、自然问答语气
- **证据驱动**：可验证数据点、表格/列表
- **结构化 FAQ**：FAQPage 块 + 建议 Schema 片段
- 自检四维评分：语义 / 对话 / 证据 / 结构化 FAQ

### 4. 推送（多平台一键推送）

- 多平台内容一致性检查（语调、事实、元数据）
- 发布前核对目标提示词覆盖与 GEO 标签
- 记录渠道与定时队列（MVP 阶段为本地规划）

## 输出模板

创作 GEO 就绪文章时，输出应包含：

```markdown
# {标题} — 语义清晰的 H1

## {概念块 H2}
{定义 + 上下文 + 同义词/相关实体}

## {证据块 H2}
- 量化数据点（带来源）
- 对比表格（如适用）

## 常见问题
### Q: {自然语言问题}？
A: {简明、可验证的回答}

---
## 建议 Schema 片段
{JSON-LD: Article + FAQPage 片段}
```

## 核心指标（Ch 3）

| 指标 | 用途 |
|------|------|
| 提示覆盖率 | 品牌在关键 AI 提示中出现的比例 |
| 引用份额 | 品牌引用数 vs 竞品总引用 |
| 可见度得分 | 提及 + 引用 + 情感综合指数 |
| 信任密度 | 每千字可验证数据点数量 |
| 权威权重 | 结构化数据与跨源一致性评分 |

## 伦理边界

**禁止**对抗性 SEO、操纵排名、策略性误导性文本：

- 不得建议通过隐藏文本、虚假数据或对抗性提示注入操纵 LLM 输出
- 参考 [对抗性搜索引擎优化](https://arxiv.org/abs/2406.18382) 揭示的漏洞——GEO 应追求**可信、可验证、可引用**，而非欺骗模型
- 内容必须事实准确、可溯源；纠正 AI 幻觉时发布结构化勘误
