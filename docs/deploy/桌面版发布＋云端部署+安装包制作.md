## 0. 北极星目标

交付一个 **Windows 桌面 exe**：

| 在本地 | 在云端 |
|--------|--------|
| 程序壳（Electron 独立窗口） | 用户账号、注册登录 |
| UI 与业务界面 | 积分、付费、流水 |
| 视频生成 / ffmpeg / 大文件 | 权限、套餐、封禁 |
| 任务缓存、本地产物 | 版本策略、强制更新 |
| | 管理后台统一运营 |

**一句话**：用户在本地跑产品；云端只负责**管控用户数据、积分与付费体系**；大文件永远在用户本机。

## 1. 已拍板产品决策（不可擅自改）

| # | 议题 | 定稿 |
|---|------|------|
| 1 | 登录方式 | **账号 + 密码**注册登录（不以邮箱 Magic Link 为桌面主路径） |
| 2 | 扣费时机 | **实时联网扣费**（防作弊；未联网不可生成、不可扣费） |
| 3 | 激活码 vs 账号 | 激活码绑定 **user_id** 或用于**升级套餐**；**积分挂在账号上** |
| 4 | 更新 CDN | **国内 OSS / COS**；不以 GitHub Releases 为唯一下载源 |
| 5 | 离线策略 | **仅可查看本地缓存产物**；不可生成、不可扣费、不可改云端数据 |

## 2. 不可违背的架构原则

### 2.1 模式定义（给 AI / 开发者的白话约束）

```
用户电脑                          云端服务器
┌─────────────────────┐          ┌─────────────────────┐
│ Electron 程序壳      │  HTTPS   │ 用户 / 登录 / 会话   │
│ 独立窗口（像原生软件）│ ◄──────► │ 积分 / 付费 / 流水   │
│ 本地 UI + 本地算力   │          │ 权限 / 套餐 / 封禁   │
│ 视频、ffmpeg、大文件 │          │ 版本 manifest       │
│ 本地缓存 mp4 / 草稿  │          │ 管理后台            │
└─────────────────────┘          └─────────────────────┘
```

- **云端**：账号、积分、付费、权限、版本策略 —— **唯一真相源（Source of Truth）**。
- **本地**：程序壳、界面、视频管线、大文件、任务缓存 —— **不算账号权威**。
- **禁止**：把「每台电脑各自一份用户积分库」当作交付方案。
- **禁止**：为省事把大视频/素材默认上传云端。

### 2.2 数据权威表

| 数据类型 | 权威位置 | 本地是否可有副本 |
|----------|----------|------------------|
| 用户账号、密码哈希、会话 | **云端** | 仅 session token / cookie，不可自建用户表当权威 |
| 积分余额、消费流水 | **云端** | 可展示缓存余额，**扣费必须以云端成功为准** |
| 权限 / 套餐 / 封禁 | **云端** | 可缓存展示，**功能开关以云端为准** |
| 激活码绑定关系 | **云端**（绑 user_id） | 本地仅存激活凭证密文 |
| 版本策略（最新版、强制更新） | **云端 manifest** | 无 |
| 安装包二进制 | **国内 CDN（OSS/COS）** | 下载后本地安装 |
| 生成的 mp4、上传素材 | **用户本机** | 权威在本地，云端不存 |
| 任务进度、草稿、对话缓存 | **用户本机** | 权威在本地（除非后续单独立项云同步） |
| API Key（DeepSeek / RunningHub 等） | **云端下发 → 本地加密缓存** | 禁止打进安装包明文 |

### 2.3 计算与管控分离

| 面 | 职责 | 协议 |
|----|------|------|
| **管控面（云端）** | 登录、积分、权限、版本检查、心跳、管理后台 | 公网 HTTPS |
| **数据面（本地）** | 视频生成、剪辑、ffmpeg、大文件 IO、任务轮询 | `127.0.0.1` 仅本机 |

**MUST**：扣积分、鉴权、权限校验在发起重计算**之前**完成，且以云端返回为准。  
**MUST**：视频 / ffmpeg / 大 payload 在**本地 FastAPI**执行。  
**NEVER**：桌面生产环境把 `CREDIT_DB_OVERRIDE` 指到用户本机 `%APPDATA%` 作为用户积分库。

### 2.4 窗口与体验

- **MUST**：用户看到的是 **Electron 独立窗口**（无地址栏、不像浏览器打开网页）。
- **MUST**：主界面通过 **`app://` 自定义协议**（或等价最优方案）加载；禁止以裸 `http://127.0.0.1:xxxx` 作为**最终用户可见形态**。
- **MAY**：内部仍运行 Next.js standalone 作为 UI 服务，但对用户**不可见、不可当网址使用**。
- **MUST**：启动有 **Splash / 加载态**，掩盖子进程启动时间。

### 2.5 更新机制（双层）

1. **策略层**：云端 `GET /api/central/manifest`（最新版、最低支持版、强制更新、更新说明、渠道）。
2. **分发层**：`electron-updater` + 国内 OSS/COS 上的 `Setup.exe` + `latest.yml`。

**MUST**：启动时检查 manifest；`force_update=true` 时**阻断旧版**继续业务。  
**MUST**：发新版本时同时具备：manifest 版本号 + CDN 可下载安装包 + `latest.yml`。

### 2.6 技术栈边界（禁止擅自替换）

| 层级 | 既定技术 |
|------|----------|
| 桌面壳 | Electron 33 + electron-builder（NSIS） |
| 自动更新 | electron-updater |
| UI | Next.js 16 standalone（内嵌） |
| 本地算力 | Embeddable Python 3.13 + FastAPI + ffmpeg |
| 云端 API | 现有 `main.py` FastAPI 体系扩展 |
| 云端管理后台 | Next.js `/admin` 扩展 |
| 云端 DB（MVP） | SQLite on Volume（`CREDIT_DB_OVERRIDE=/data/accounts.db`） |
| 云端 DB（规模化） | 托管 PostgreSQL（后期迁移，不挡 MVP） |
| 安装包 CDN | 阿里云 OSS / 腾讯云 COS |

**禁止**：擅自换 Tauri / WPF / Qt；擅自新建平行后端栈；MVP 阶段强行上自建 MySQL 集群。

### 2.7 登录与激活（定稿语义）

```
用户注册账号（账号+密码）→ 云端 users
    │
    ├─ 积分账户 credit_accounts 挂在 user_id
    │
    └─ 可选：输入激活码
            → 绑定 user_id / 升级套餐 / 下发 API Key
            → 不单独成为「另一套积分体系」
```

- 登录主路径：**账号 + 密码**。
- 激活码：**许可 / 套餐 / Key 下发**，绑定到账号，**积分只认 user_id**。
- 管理员后台管的是**云端用户与积分**，不是某台电脑的本地库。

### 2.8 离线与联网

| 状态 | 允许 | 禁止 |
|------|------|------|
| 在线且已登录 | 全功能（扣费走云端） | — |
| 离线或未登录 | 仅浏览本地已生成缓存 | 生成视频、扣费、改积分、注册 |

## 4. API 分流契约

| 路由类别 | 请求目标 | 示例 |
|----------|----------|------|
| 注册 / 登录 / 登出 / 当前用户 | **云端** | `/api/auth/*` |
| 积分余额 / 消费 / 兑换 / 流水 | **云端** | `/api/credit/*` |
| 版本 / 心跳 / 激活 | **云端** | `/api/central/manifest`、`/heartbeat`、`/activate` |
| 视频生成 / 剪辑 / 状态 / 取消 | **本地** `127.0.0.1:8010` | `/api/video/*` |
| 管理后台 | **云端**（浏览器访问 admin 域名） | `/admin/*`、`/api/credit/redeem-codes` 等 |

**扣费顺序（定稿）**：

```
用户点击「生成」
  → 本地 UI 确认已登录
  → 云端鉴权 + 实时扣费（失败则中止）
  → 本地 FastAPI 执行视频管线
  → 产物写入本机 video-cache
  → 云端流水已有记录（ref_id 幂等）
```

环境变量契约（桌面生产）：

```env
# 云端（构建写入或首次配置）
CLOUD_API_URL=https://api.yourdomain.com
CENTRAL_SERVICE_URL=https://api.yourdomain.com

# 本地（Electron 主进程注入）
FASTAPI_URL=http://127.0.0.1:8010
# 视频 static 等本地资源可指向本地；账号/积分请求必须走 CLOUD_API_URL
DATA_DIR=<userData>/video-cache
VIDEO_BGM_DIR=<resources>/bgm

# 禁止：桌面生产把 CREDIT_DB_OVERRIDE 指到本机用户目录作为账号库
```

云端生产：

```env
CREDIT_DB_OVERRIDE=/data/accounts.db
DATA_DIR=/data
DEV_EMAIL_MODE=0
# 账号密码登录所需盐与管理员密钥等见 .env.example
CENTRAL_LATEST_VERSION=0.1.0
CENTRAL_FORCE_UPDATE_BELOW=0.0.1
CENTRAL_UPDATE_URL=https://cdn.yourdomain.com/releases/
```

## 6. 云端部署方案

### 6.1 最小拓扑

```
                    Internet
                        │
          ┌─────────────┴─────────────┐
          │   Nginx / 平台 Ingress     │
          └─────────────┬─────────────┘
                        │
        ┌───────────────┼───────────────┐
        ▼               ▼               ▼
  api.xxx.com    admin.xxx.com    cdn.xxx.com
  (FastAPI)      (Next.js Admin)  (OSS/COS)
   :8000           :3000          Setup.exe
        │               │         latest.yml
        └───────┬───────┘
                ▼
         Volume /data
         accounts.db（全用户共用）
```

### 6.2 服务清单

| 服务 | 镜像/形态 | 职责 |
|------|-----------|------|
| **api** | `Dockerfile.api` | 账号密码登录、积分、激活、manifest、心跳 |
| **web/admin** | `Dockerfile.web` | 管理后台（用户、积分、激活码、版本配置） |
| **CDN** | 阿里云 OSS / 腾讯云 COS | 安装包与 `latest.yml`，国内可访问 |

MVP：**api 与 admin 可同域不同路径**，或双容器；**激活服务合并进同一 FastAPI**，不必单独拆库。

### 6.3 云端数据库

| 阶段 | 方案 |
|------|------|
| MVP（几十～几百用户） | SQLite 文件 `/data/accounts.db` + Volume + **每日备份** |
| 规模化 | 托管 PostgreSQL，迁移 `lib/db.py` |

**不需要**一开始单独买「数据库专用服务器」。需要的是：**所有客户端共用一份云端库**。

### 6.4 管理后台能力（目标清单）

| 能力 | 优先级 | 说明 |
|------|--------|------|
| 管理员登录 | P0 | 已有基础 |
| 兑换码批次生成/查看 | P0 | 已有 |
| 用户列表 / 搜索 | P0 | 需扩展 |
| 单用户积分调整（admin_adjust） | P0 | 常量已有，UI/API 需补 |
| 用户封禁 / 禁用 | P1 | 权限管控 |
| 激活码创建 / 吊销 / 绑用户查看 | P1 | 与 user_id 关联 |
| 版本发布（最新版号、强制更新阈值、CDN 路径） | P1 | 可先 env，后做 UI |
| 消费流水 / 对账 | P2 | 客服与财务 |

### 6.5 云端部署检查清单

- [ ] 域名 + HTTPS（`api` / `admin`）
- [ ] Volume 挂载 `/data`，`CREDIT_DB_OVERRIDE=/data/accounts.db`
- [ ] 账号密码注册登录可用
- [ ] 积分扣费、兑换码、管理员调账可用
- [ ] manifest 返回正确版本与 `CENTRAL_UPDATE_URL`（指向国内 CDN）
- [ ] 激活码可创建，且可绑定 user_id / 套餐
- [ ] `accounts.db` 定时备份
- [ ] CORS / Cookie 域配置允许桌面客户端与管理后台

详细命令见 [PAAS.md](./PAAS.md)、[CENTRAL-ACTIVATION.md](./CENTRAL-ACTIVATION.md)。

## 7. 软件更新方案

### 7.1 双层结构

```
策略层（云端 API）
  GET /api/central/manifest?client_version=x.y.z
  → latest_version / min_supported_version / force_update
  → release_notes / channel / update_url

分发层（国内 OSS/COS）
  /releases/AI营销获客中台-Setup-1.2.0.exe
  /releases/latest.yml
```

### 7.2 客户端流程

```
启动 → Splash
  → GET manifest
      ├─ force_update → 阻断对话框 → 下载安装 → 退出重启
      ├─ 有新版本 → 标记，设置页/托盘提示
      └─ 已最新 → 继续
  → 登录（账号+密码，云端）
  → 启动本地 Next + FastAPI
  → 主窗口 app://
  → 后台可选：用户确认后 electron-updater 下载
```

### 7.3 发版运维动作

1. 构建新安装包（§8）。
2. 上传 `Setup-x.y.z.exe` 与 `latest.yml` 到 OSS/COS。
3. 更新云端 `CENTRAL_LATEST_VERSION`（及必要时 `CENTRAL_FORCE_UPDATE_BELOW`）。
4. 抽测：旧版客户端能检测到更新；强制更新版本无法进入业务。

## 8. 安装包制作方案

### 8.1 技术

| 项 | 值 |
|----|-----|
| 壳 | Electron 33 |
| 打包 | electron-builder → NSIS |
| 产物 | `release/AI营销获客中台-Setup-<version>.exe` |
| 内嵌 | Next standalone、Python 3.13、ffmpeg、BGM、main.py |
| 更新元数据 | `latest.yml`（与 exe 同目录上传 CDN） |

### 8.2 构建机要求

| 项 | 说明 |
|----|------|
| OS | Windows 10/11 x64 |
| 路径 | **纯 ASCII**（如 `C:\build\zhongtai-main`），避免中文路径导致 electron-builder `ENOENT` |
| Node | 22.x |
| pnpm | 9.x |
| ffmpeg | `tools/ffmpeg/bin/ffmpeg.exe` 已存在 |
| 网络 | 首次 `resources:build` 需下载 embeddable Python |

### 8.3 构建环境变量（示例）

```env
CENTRAL_SERVICE_URL=https://api.yourdomain.com
CLOUD_API_URL=https://api.yourdomain.com
CENTRAL_SIGNING_PUBLIC_KEY=<与云端私钥配对的公钥 PEM>
# publish / updater 指向国内 CDN，例如：
# https://cdn.yourdomain.com/releases/
```

**禁止**把生产 AI Key 打进安装包；Key 由云端激活/登录后下发并写入本地加密凭证。

### 8.4 命令链（目标流程）

```powershell
pnpm install
pnpm electron:build
pnpm resources:build    # Next standalone + Python bundle + ffmpeg，约 10–20 分钟
pnpm preflight          # 必须通过
pnpm dist:win           # 产出 release/*.exe
```

构建后：

1. 将 `Setup-*.exe` 与 `latest.yml` 上传至 **OSS/COS**。
2. 更新云端 manifest 版本号。
3. 用干净 Windows 机做安装验收（§8.6）。

当前命令细节见 [ELECTRON-BUILD.md](./ELECTRON-BUILD.md)；**实施混合 API / app:// / 国内 CDN 后，以本文契约为准更新该手册**。

### 8.5 安装包内运行时布局（概念）

```
安装目录 / resources/
  python/           # embeddable Python
  ffmpeg/bin/       # ffmpeg / ffprobe
  next-standalone/  # UI
  bgm/
  main.py + routes/

用户数据 %APPDATA%/AI营销获客中台/
  video-cache/      # 大文件、产物
  credentials.bin   # 激活/Key 密文
  logs/
  # 无 accounts.db 作为账号权威（账号在云端）
```

## 10. 分期里程碑（执行顺序）

```
M1 云端管控基座 → M2 更新链路 → M3 桌面混合 API → M4 独立窗口体验 → M5 安装包发版
```

| 里程碑 | 交付物 | 完成标准 |
|--------|--------|----------|
| **M1 云端管控基座** | 公网 API + 集中 DB + 管理后台最低可用 | 账号密码注册登录；积分扣费；管理员可见用户并调账 |
| **M2 更新链路** | OSS/COS + manifest + electron-updater | 旧版可检测更新；强制更新可阻断 |
| **M3 桌面混合 API** | 桌面 auth/credit 走云端；本地仅算力 | 本机无用户积分权威库；断网不可生成 |
| **M4 独立窗口体验** | `app://` + Splash + 激活/登录接入启动链 | 用户感知为原生软件 |
| **M5 安装包发版** | `dist:win` + CDN 上传 + 验收清单全过 | 可对真实用户分发 |

**硬约束**：M1 未完成前，不得将「本地 SQLite 用户库」作为统一管理方案交付。

## 11. AI / 开发者执行自检清单

执行任何改动前，用白话自检（对应产品意图）：

| # | 自检问题 | 正确理解 |
|---|----------|----------|
| 1 | 账号 / 积分 / 付费改动是否走**云端**？ | 用户在本地壳里用产品；**管控数据只在云端**。Web 管理后台与桌面客户端共用同一云端用户库。 |
| 2 | 窗口是否仍像打开 localhost 网页？ | 取最优解：**独立 Electron 窗口 + `app://`（或等价）**，内部可有本地服务，用户不可见裸 URL。 |
| 3 | 是否把大文件上传云端？ | **禁止默认上传**。云端只存用户、积分、权限等核心数据；mp4/素材在用户本机。 |
| 4 | 是否把用户账号库写回本机 SQLite？ | **禁止作为权威**。本机只存缓存、产物、加密凭证。 |
| 5 | 扣费是否绕过服务端定价与幂等？ | **禁止**。必须走云端实时扣费与既有定价/幂等机制（如 `lib/api_auth.py` 体系）。 |
| 6 | 发版是否同时有 manifest + CDN 安装包？ | **必须同时有**。策略在云端，包在国内 OSS/COS。 |
| 7 | 新数据属于云端权威还是本地缓存？ | 账号/积分/权限/版本 → **云端**；视频/草稿/任务进度 → **本地**。 |
| 8 | 打包前 preflight、云端 API、CDN 是否可用？ | **必须全部可用**再分发安装包。 |

│ 云端 Admin      Next.js（Dockerfile.web）                         │
│ 云端 DB MVP     SQLite @ /data/accounts.db（Volume）              │
│ 登录            账号 + 密码（云端）                                 │

│ 积分            云端实时扣费 + 流水幂等                             │
