# 企业智能体团队运维手册

## 1. 组成与职责

团队由 1 位总协调官、10 个企业通用部门和 4 位 AI 内容行业专家组成。角色真源位于 `lib/agents/registry.ts`；展示层不得另建一套角色名单。每个角色都包含稳定 ID、版本、专业级别、语言风格、输出合同、知识范围和工具权限。

角色升级时先提高 `version`，再同步评测。不得用公众人物姓名、头像或模仿提示替代专业合同。

## 2. Skill 管理

Skill 真源位于 `lib/agents/skills.ts`。每项 Skill 必须包含版本、方法、风险、来源类型、来源链接、适用角色和所需工具。系统只向当前角色加载已分配 Skill，客户端看不到完整指令。

- `official`：政府、监管机构或正式标准，可作为规则依据。
- `reference`：公开项目和方法案例，只能作为参考。
- `company`：公司制度与方法，须由授权人员维护。

法务、财务、人事等高风险 Skill 更新后必须重新运行边界评测，并检查资料日期和适用范围。

## 3. 云端模型路由

云端服务实施、数据库保护、灰度和回滚的完整要求见
[`docs/deploy/CLOUD-ENTERPRISE-AGENT-MODEL-REQUIREMENTS.md`](deploy/CLOUD-ENTERPRISE-AGENT-MODEL-REQUIREMENTS.md)。

客户端不展示、不接收也不信任模型 ID。`lib/agents/model-router.ts` 只读取服务端同步的云模型候选，并按能力、优先级和故障切换预算选择。企业智能体必须使用独立渠道，不得复用文案创作或其他业务的通用模型候选。

云端模型中心下发的企业智能体渠道必须同时满足：

- `kind = "llm"`；
- `adapter = "openai_chat"`；
- 模型名或渠道名属于 DeepSeek；
- `extra.purpose = "enterprise_agent"`；
- `extra.performance_tier = "fast"`；
- 需要处理图片时，渠道还必须声明 `extra.supports_images = true`。

示例（仅展示结构，密钥由云端加密同步）：

```json
{
  "kind": "llm",
  "name": "企业智能体快速通道",
  "adapter": "openai_chat",
  "base_url": "https://provider.example",
  "api_key": "<cloud-secret>",
  "model": "deepseek-fast-model",
  "priority": 20,
  "extra": {
    "purpose": "enterprise_agent",
    "performance_tier": "fast",
    "supports_images": true
  }
}
```

每次成功调用在内部运行事件中保留路由快照；公开响应只显示“服务端路由”和成功调用次数，具体渠道、模型 ID 与失败详情不返回客户端。

如果没有可用候选，任务返回 `MODEL_NOT_CONFIGURED`；全部候选失败时返回 `CLOUD_MODEL_UNAVAILABLE`。没有成功模型调用时不得扣费。

## 4. 附件与知识范围

支持最多 6 张图片和 5 份文档，单文件 20MB。文档格式为 PDF、DOCX、XLSX、PPTX、TXT、MD、CSV；旧版 DOC 不支持。OOXML 有单块和总解压大小限制，MIME 与扩展名冲突时拒绝。

知识范围：

- `temporary`：只进入当前请求，不写入长期知识库。
- `department`：仅当前用户的指定部门可检索。
- `company`：当前用户的所有部门可检索。
- `task`：只允许同一个持久化任务 ID 检索。

附件和检索片段始终作为“不可信证据”进入用户层，不得进入系统指令。知识服务故障时任务可以继续，但必须返回 `knowledge_unavailable`。

## 5. 协作与状态

一个任务只有一个主责角色，最多三个会签角色。直接选择部门时该部门保持主责；选择总协调官时由确定性领域规则分诊。会签并行执行，多部门成功后再由总协调官汇总。

工作区展示的是可审计的业务事件链：读取材料 → 分诊 → 主责办理 → 并行会签 → 总协调汇总 → 形成结论。它不展示模型私有思维过程；排队、处理中、完成、失败和跳过必须来自真实编排状态，不得用循环动画伪造进度。

- `completed`：主责和所需会签均完成，汇总可用。
- `partial`：主责结果可用，但会签或汇总至少一项失败。
- `failed`：主责无可用结果。
- `cancelled`：调用方取消，不得继续执行或声称完成。

真实专业分歧必须保留，不得为了“统一口径”删除阻断意见。

## 6. 工具与审批

- T0：只读检索和分析，可自动执行。
- T1：内部草稿和可逆准备，可自动执行。
- T2：对外发送、正式发布或业务写入，必须人工审批。
- T3：付款、签署、最终人事决定、绕过验证等，由智能体永久阻断。

审批绑定用户、任务、动作类型、完整参数哈希、有效期和版本。执行前重新读取审批并核对参数。执行证据写入后不可覆盖；已有证据的审批不得重放。邮件、日历、CRM 没有已配置连接器时保持 `needs_configuration`。

现有内容发布适配器还会检查目标平台账号身份和登录状态。自动化测试不得真实发布。

## 7. 数据与审计

SQLite 使用七张表：运行、成员、事件、知识文档、知识片段、审批、执行证据。所有公开查询必须带 `user_id`。内部检索、事件追加、状态更新和执行证据写入还需要 `X-Metered-Key`。

排查顺序：运行记录 → 事件 → 成员结果 → 知识命中 → 审批 → 执行证据 → 计费引用。外部动作只有适配器返回可验证证据后才能标记完成。

## 8. 验证清单

发布前至少验证角色注册、Skill 映射、模型故障切换、附件格式、用户/部门/任务隔离、审批过期与参数不匹配、执行重放、部分会签、移动布局和深色模式。浏览器本地构建不等于外部发布 UAT；真实邮件、日历、CRM 和内容发布必须在授权测试账号上单独验收。
# 功能工作台业务助理边界

工作台的业务助理与“企业智能体团队”并行存在，但职责不同：

- 视频创作助理：跟进视频项目目标、阶段计划、当前页面和生成任务状态。
- GEO 助理：跟进企业知识、内容矩阵、文章生成与评分优化。
- 两者统一复用身份定位基础记忆；各自只读取本专业记忆。
- 抖音截流助理仅保留注册位，不允许调用；身份定位和海报图创作不提供助理。
- 助理对话返回的动作只允许页面跳转和待用户采用的计划。生成、扣费、发布、删除及外部触达不得由对话直接执行。
- 项目完成状态必须由草稿保存、运行任务终态或 GEO 评分等证据推进，不能以模型文本作为完成证据。
