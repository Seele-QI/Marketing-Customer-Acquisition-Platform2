# 一键分发栏目设计

## 目标

在现有单页工作台中增加“一键分发”一级栏目，下设“视频一键分发”和“GEO 文章一键分发”两个子板块。视频分发首版以抖音真实可用为验收目标，采用可见 Chrome 自动化并允许用户在验证码场景接管；其他视频平台保留状态展示但标记为待验证。GEO 文章分发首版只实现完整工作区骨架，不调用未完成的发布接口。

## 信息架构

- 侧栏一级栏目：一键分发。
- 子板块：视频一键分发、GEO 文章一键分发。
- 页面状态继续复用现有 `MainView` 单页路由模式，不引入新的 URL 路由系统。
- 账号绑定放在视频分发工作区内，通过页内切换进入，避免新增第三个业务子板块。

## 视频一键分发

作品可来自现有视频历史记录、本地上传或可解析的视频 URL。用户编辑标题、描述和标签，也可调用现有 DeepSeek 计费链路生成发布文案。发布前必须通过登录、视频地址、标题、后端可用性检查。

抖音首版采用可见 Chromium：系统自动打开创作者中心、上传视频并填写文案；如出现扫码、短信或验证码，界面进入“等待用户操作”状态；发布成功后回传平台、时间和作品链接，失败时显示明确错误并保留重试入口。

小红书、快手和视频号展示账号连接状态，但在首版 UI 中标记为“待验证”，不默认进入正式发布队列。

## GEO 文章一键分发

页面展示文章来源、目标平台、平台适配预览和发布记录。来源入口指向现有 GEO 深度优化文章编辑器；公众号、知乎、百家号和小红书图文等平台以“即将开放”状态呈现。发布按钮禁用，不发送网络请求，也不生成模拟成功数据。

## 接口与数据流

- Next.js API Route 使用现有 `proxyToFastapi` 转发账号连接和发布请求。
- FastAPI 继续使用现有 `require_user`，所有账号 Cookie 按 `user_id` 隔离并使用 `COOKIE_ENCRYPTION_KEY` 加密。
- `/api/connectors/*` 管理平台状态和可见浏览器登录。
- `/api/publish/accounts` 返回已绑定平台。
- `/api/publish` 执行单平台发布；首版 UI 只开放抖音。
- `/api/ai/publish-copy` 复用现有认证、积分扣费和 DeepSeek 调用。

## 错误处理

- 未登录、未绑定账号、视频不可用、标题为空和后端不可达在发布前阻断。
- 浏览器启动、登录轮询、上传和发布阶段分别显示状态，不允许重复提交。
- 登录超时或浏览器被关闭后恢复为可重试状态。
- 后端缺少 Playwright 或 Chromium 时返回可执行的安装提示。
- GEO 文章分发不调用未完成接口，因此不存在伪失败或伪成功状态。

## 验收

- 侧栏能展开“一键分发”并切换两个子板块，面包屑同步更新。
- 视频页能读取现有视频、上传视频、生成文案、绑定抖音账号并启动可见浏览器发布。
- 抖音未绑定或后端未就绪时能给出明确提示。
- 其他视频平台不可误触发正式发布。
- GEO 文章页完整可见、移动端可用，发布操作明确禁用。
