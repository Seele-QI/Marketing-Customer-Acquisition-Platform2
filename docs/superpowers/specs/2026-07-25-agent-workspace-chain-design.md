# 企业智能体嵌入式工作台与任务链设计

## 目标

点击“交给总协调官分诊”或任一企业智能体后，不再打开覆盖整个应用的全屏层。工作台嵌入 AI 中台现有主壳，持续保留全局左侧导航、顶栏、登录、积分和主题能力；任务处理过程使用类似 Codex 的纵向事件链展示。

## 已选方案

采用“中台主壳内嵌工作台”：

- 全局 `DashboardSidebar` 和 `TopHeader` 始终保留。
- 企业智能体工作台只占内容区，不再使用 `fixed inset-0` 或 `h-dvh`。
- 工作区内部取消第二套部门侧栏，改为顶部智能体切换、中央任务链、右侧联合办理与审批面板。
- 返回按钮回到智能体总览；点击全局导航时正常离开工作台。
- 文案智能体已有独立全屏交互暂不改变。

不采用：

- “全屏层向右偏移 240px”：仍会绕过中台内容容器，移动端和顶栏状态容易分裂。
- “新建独立路由”：会重复登录、积分、任务运行时和业务助理上下文。

## 独立 DeepSeek 快速模型通道

企业智能体不得复用文案创作的通用候选模型顺序。模型仍由云端同步配置 `MODEL_PROVIDERS_JSON_B64` 下发，但只有同时满足以下条件的渠道可进入企业智能体候选集：

- `kind = "llm"`；
- `adapter` 为 OpenAI 兼容聊天适配器；
- `extra.purpose = "enterprise_agent"`；
- `extra.performance_tier = "fast"`；
- 渠道名称或模型 ID 属于 DeepSeek 家族；
- 图片任务还必须声明 `extra.supports_images = true`。

客户端不提交模型 ID，也不获得具体供应商、地址、密钥和模型 ID。界面只显示“DeepSeek 快速通道 · 云端下发”。专用通道未配置时返回明确的 `MODEL_NOT_CONFIGURED`，不回退到 GPT、Claude、豆包或普通 DeepSeek 环境变量。

## Codex 式任务处理链

展示的是可审计业务事件，不展示模型私有思维链或逐字推理。任务链包含：

1. 读取任务与附件；
2. 总协调官分诊；
3. 主责部门办理；
4. 会签部门并行复核（0–3 项）；
5. 总协调官汇总；
6. 形成可复核结论。

状态仅使用：

- `queued`：尚未开始；
- `active`：真实请求正在执行；
- `completed`：已有可用结果；
- `failed`：该节点失败；
- `skipped`：任务不需要该节点。

前端发起任务时先调用只读规划接口取得真实主责和会签方案，再调用执行接口。执行期间主责与会签节点显示为进行中；执行结束后由服务端返回最终任务链。失败会签保留为红色节点，整体结果标为 `partial`，不得渲染成全部完成。

## 接口与数据边界

- 新增 `POST /api/agents/plan`：认证后执行确定性分诊，不调用模型、不扣积分。
- `POST /api/agents/run` 返回新增的公开 `trace` 字段。
- 新增 `lib/agents/task-trace.ts`：统一生成规划态和结果态任务链。
- `lib/agents/model-router.ts` 只读取企业智能体专用云端渠道。
- 历史接口继续脱敏，不返回模型 ID、供应商或原始路由快照。

## 界面

视觉延续 AI 中台已有浅灰背景、白色内容面、蓝色主操作和低饱和状态色：

- 内容区顶部为紧凑工具栏：返回、智能体身份、云端快速通道、自动会签。
- 中央为任务输入、纵向处理链和最终结论。
- 处理链使用连续竖线、状态圆点、时间顺序和简短可审计说明，避免聊天气泡堆叠。
- 右侧保留联合办理、审批执行、任务凭证和最近任务。
- 小屏隐藏右侧栏，将任务链保持为单列。

## 失败与安全

- 规划接口失败时执行接口仍可尝试，但任务链明确显示“分诊信息暂不可用”。
- 专用模型缺失、超时、会签失败、汇总失败分别显示真实状态。
- 停止任务使用现有 `AbortController`，节点进入失败/停止状态，不展示伪完成。
- 附件继续视为不可信证据；外部发布、通知和其他 T2 动作仍需人工审批。

## 验收标准

- 点击总协调官后，全局左侧导航和顶栏仍可见、可操作。
- 内容工作台没有 `fixed inset-0`、没有 `h-dvh`。
- 企业智能体候选模型仅来自云端专用 DeepSeek 快速通道。
- 客户端请求和公开历史均不包含模型 ID。
- 发起任务后立即出现真实规划链，完成后每个主责/会签节点状态与服务端结果一致。
- `partial`、失败、取消、无会签场景均有明确视觉状态。
- 桌面端、390px 移动端、浅色和深色模式通过浏览器验收。
