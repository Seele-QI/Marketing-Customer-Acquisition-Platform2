# 图片工作台生成数量自定义设计

## 目标

为“海报图创作”和“图片创作”增加可控的生成数量选项。用户可以在提交前明确选择生成 1、2、3 或 4 张图片，并清楚看到本次所需积分。

## 产品规则

- 支持数量：1、2、3、4 张。
- 默认数量：2 张。
- 两个创作模式分别保存自己的数量选择，切换模式时不互相覆盖。
- 当前单张价格为 20 积分，总价按“单张价格 × 生成数量”计算。
- 生成按钮展示“生成 N 张 · M 积分”，让扣费在提交前可见。
- 不提供任意数字输入，避免误填造成高并发或意外扣费。

## 界面设计

数量选择器放在左侧设置面板的分辨率设置附近，使用与比例、分辨率控件一致的分段按钮：

`1 张`、`2 张`、`3 张`、`4 张`

选中项沿用工作台的蓝色主强调色。底部提示词输入区的生成按钮同步展示当前数量和总积分，不增加新的弹窗或确认步骤。

结果画布根据返回数量自动布局：

- 1 张：单图居中展示。
- 2 张：双列展示；窄屏转为单列。
- 3–4 张：桌面端两列网格；窄屏单列。

## 数据合同

前端生成请求继续使用 `count` 字段，允许整数 1–4。海报图和图片创作共用同一合同。

服务端必须再次校验 `count`，拒绝缺失范围以外的值，不能信任客户端。任务记录保存请求数量，生成管线按该数量创建候选任务，进度文案使用实际数量。

任务结果继续返回 `image_urls`。部分候选失败时，只返回成功图片，并给出“已生成 X/N 张”的非技术性提示；全部失败时任务失败。

## 计费

`poster_image` 与 `image_creation` 保持独立计费场景和相同的单张价格。Next.js 鉴权代理在提交生成前按 `count` 计算总价，并执行一次对应总额的原子扣费。

扣费参数必须包含生成数量，后端计价只能接受 1–4 的整数。非法数量在扣费前返回 400。重复计费防护继续使用唯一请求引用。

本次不改变单张价格，不新增计费场景，也不在用户界面暴露底层图片服务或工作流信息。

## 错误与边界处理

- 数量不是整数或不在 1–4：请求拒绝，不扣积分。
- 积分不足：沿用现有余额不足提示，不提交生成任务。
- 部分生成失败：任务成功并返回已生成图片，同时显示完成数量。
- 全部生成失败：沿用现有脱敏失败提示。
- 切换创作模式：保留各模式自己的数量、提示词和其他设置。

## 测试与验收

- 类型解析测试覆盖 1、2、4 的合法请求以及 0、5、小数和字符串等非法输入。
- API 路由测试验证数量被转发，并按数量计算扣费。
- Python API 测试验证 1–4 校验、任务记录和候选调用次数。
- 管线测试验证请求 1、3、4 张时的成功数量及部分失败提示。
- UI 合同测试验证数量控件、默认 2 张、按钮总价和模式状态隔离。
- 浏览器验收覆盖桌面与移动端布局，不触发真实付费生成。
