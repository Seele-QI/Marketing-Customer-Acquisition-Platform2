# 账号级用户长期记忆系统设计

日期：2026-07-22
状态：已批准

## 目标

将现有文案创作中的设备本地摘要升级为账号级云端长期记忆系统。系统持续从用户自己的对话中提取稳定信息，支持跨设备同步、分层使用、冲突替换、偏好增强与衰减，并让用户能够查看、修改、停用和删除记忆。

本阶段只同步长期记忆，不包含聊天历史跨设备同步。

## 已锁定的产品决策

- 记忆绑定登录账号，云端为唯一事实源，支持跨设备和客户端重装后的同步。
- 采用“全局基础档案 + 模块独立记忆”：身份、行业和业务资料全局共享；文案、身份定位、GEO 等模块保存各自偏好和约束。
- 普通非敏感信息自动写入；用户可随时查看、修改、停用和删除。
- 新信息与旧信息冲突时，以用户最新明确表述为准；旧值保留变更记录，但不再注入模型。
- 对话区保留快捷记忆条，并新增独立记忆中心。
- 第一版保存身份/行业、业务资料、长期目标、内容偏好、明确禁忌和长期事实；临时任务不进入长期记忆。
- 身份与业务事实长期有效；表达偏好随重复确认增强，长期未出现则降低检索权重。
- 每次只检索当前任务相关的记忆，并展示本次实际使用的记忆。
- 只从用户明确表达或用户手动填写的内容中建立事实；AI 回复不得成为用户事实来源。

## 现状与迁移边界

当前实现位于 `lib/user-memory.ts`、`app/api/ai/memory-extract/route.ts` 和 `components/copywriting-chat-workspace.tsx`：

- 记忆保存在浏览器 `localStorage` 的 `copywriting-user-memory-v1` 中，不能跨设备。
- 数据是单份 JSON，只有行业、角色、目标、偏好和事实数组。
- 最近六条消息中至少出现两条用户消息后，浏览器调用提取接口。
- 合并逻辑仅追加和去重，不能处理冲突、版本、来源、确认和衰减。
- `/api/ai/chat-stream` 信任浏览器提交的 `memoryContext`。
- 记忆编辑区目前只能展示或清空，不能管理单条记忆。

迁移后，云端记录是唯一事实源。本地仅保留脱敏缓存和一次性迁移标志，不得在离线状态下覆盖云端。登录用户首次加载记忆时，将旧版 localStorage 内容转换为低风险的结构化候选并提交一次性导入；服务端通过导入幂等键避免重复迁移。导入成功后保留只读缓存，客户端不再直接合并本地记忆。

## 总体架构

```text
用户消息
  -> 记忆观察任务
  -> 结构化提取
  -> Schema 校验
  -> 敏感信息过滤
  -> 去重、增强或冲突替换
  -> 云端原子记忆账本

当前模块 + 当前分身 + 当前任务
  -> 相关记忆检索
  -> 上下文预算裁剪
  -> 服务端注入模型提示词
  -> SSE 返回本次使用的记忆元数据
```

系统拆分为五个独立单元：

1. **Memory Store**：保存当前有效记忆、版本关系和只追加事件。
2. **Memory Observation**：接收用户消息并生成幂等观察任务。
3. **Memory Consolidation**：执行结构化提取、过滤、去重、增强和替换。
4. **Memory Retrieval**：按账号、范围、分类、相关性和上下文预算返回当前有效记忆。
5. **Memory UI**：提供对话快捷条、使用说明和完整记忆中心。

## 数据模型

### user_memory_items

每条原子记忆至少包含：

- `id`
- `user_id`
- `scope`：`global` 或模块标识，例如 `copywriting`、`positioning`、`geo`
- `category`：`identity`、`business`、`goal`、`preference`、`constraint`、`fact`
- `memory_key`：稳定语义键，例如 `industry`、`role`、`target_customer`、`tone`
- `value_json`：结构化当前值
- `normalized_value`：用于去重与轻量全文匹配的标准化文本
- `status`：`active`、`superseded`、`disabled`、`deleted`
- `confidence`：提取置信度
- `strength`：重复确认和衰减后的使用权重
- `source_type`：`conversation`、`manual`、`legacy_import`
- `source_excerpt`：经过敏感信息过滤的短摘要，不保存完整原始消息
- `source_session_id`、`source_message_id`：可选来源定位
- `supersedes_id`：新值替换的旧记录
- `first_seen_at`、`last_confirmed_at`、`last_used_at`
- `expires_at`：仅对允许过期的类型设置
- `revision`
- `created_at`、`updated_at`

同一用户、范围、分类和稳定键只允许一个 `active` 值。所有读写都必须带 `user_id` 条件。

### user_memory_events

只追加的审计事件，记录 `create`、`reinforce`、`supersede`、`manual_edit`、`disable`、`restore`、`delete`、`purge` 和 `used`。事件包含操作前后摘要、来源、操作者和时间，不直接注入模型。

### user_memory_observations

保存待处理用户消息的幂等任务：

- 以用户、会话、消息 ID 或内容哈希构成幂等键。
- 状态为 `pending`、`processing`、`completed`、`retryable`、`failed`。
- 保存重试次数、下次重试时间和脱敏错误码。
- 只保存完成提取所需的最小用户文本；处理完成后按保留策略缩减或清除正文。

### user_memory_settings

保存账号级开关、模块开关、自动提取策略和旧版迁移状态。默认启用自动完善，但首次展示明确告知敏感信息不会保存，并允许用户关闭。

## 记忆分类与生命周期

### 创建与增强

- 用户首次明确表达稳定信息时创建记忆。
- 相同语义再次出现时不创建重复记录，而是提高 `strength` 并更新 `last_confirmed_at`。
- 人工创建或编辑的记忆优先级高于自动提取结果。

### 冲突与替换

- 用户最新明确表达的新值创建为新的 `active` 记录。
- 旧记录改为 `superseded`，并通过 `supersedes_id` 与事件记录保留版本链。
- 自动提取不能用低置信结果覆盖人工编辑值；必须积累更强证据或等待用户再次明确表达。
- `superseded`、`disabled` 和 `deleted` 记录均不得参与模型上下文。

### 衰减

- `identity`、`business` 和稳定 `fact` 默认不自动衰减。
- `preference` 和软性 `goal` 根据重复确认、最近使用和时间降低 `strength`，但不自动删除。
- 明确 `constraint` 在用户修改前保持高优先级。
- 临时任务、一次性素材要求和当前会话操作不创建长期记忆。

### 删除

- 停用只改变使用状态，可恢复。
- 删除后立即停止参与检索，并进入短期可恢复状态。
- 回收期结束后执行彻底清除，同时清理可识别来源摘要。
- “清空全部记忆”在所有设备立即失效，本地缓存同步清除。

## 敏感信息策略

在模型提取前后各执行一次服务端过滤。以下内容不得写入记忆正文、来源摘要、审计详情或应用日志：

- 密码、验证码、访问令牌、API Key、Cookie 和私钥
- 身份证件号、银行卡号和支付信息
- 完整手机号、完整邮箱、完整住址等联系方式
- 明确标记为保密或不希望记住的内容

过滤命中时生成不可逆的分类统计或统一错误码，不保存原文。日志只允许记录用户 ID、任务 ID、记忆分类、模型、状态和耗时。

## 持续提取与合并

- 用户发送消息后，服务端创建幂等观察任务；对话生成不等待记忆处理完成。
- 明确身份、行业、业务变化、长期目标和禁忌等高价值信息优先处理。
- 普通偏好按小批次合并处理，减少模型调用与重复记忆。
- 提取模型必须返回受约束 JSON Schema，操作仅允许 `create`、`reinforce`、`supersede`、`ignore`。
- 输出必须包含范围、分类、稳定键、结构化值、置信度、是否长期稳定和简短依据。
- 服务端执行 Schema 校验、敏感过滤、标准化、去重和冲突检查后才允许事务写入。
- 提取失败进入有上限的退避重试，不影响当前聊天，不向用户收取创作积分。
- 全部失败时保留可重试状态和脱敏错误，不伪装为已同步。

## 相关记忆检索

检索输入为 `user_id`、当前模块、当前分身和用户当前任务文本。

候选规则：

1. 仅查询当前用户的 `active` 记录。
2. 全局记忆始终可成为候选。
3. 当前模块记忆优先；其他模块记忆默认排除。
4. 人工确认和明确约束优先于自动偏好。
5. 使用分类匹配、稳定键匹配、轻量全文匹配、`strength` 和最近确认时间进行排序。
6. 对数量和总字符数设置硬预算，避免挤占当前任务和对话历史。
7. 返回记忆 ID、分类、摘要和最终使用顺序，供界面解释。

第一版不引入向量数据库。结构化检索不足时，可在后续阶段为非敏感摘要增加语义召回，但结构化账本始终是事实源。

## 模型上下文与接口兼容

- `/api/ai/chat-stream` 在服务端执行记忆检索和提示词注入。
- 客户端旧字段 `memoryContext` 暂时保留为兼容字段，但服务端忽略，不能覆盖账号记忆。
- SSE 正文、`billing` 和 `billing_error` 保持兼容；新增独立 `memory` 元数据事件，包含本次使用的记忆摘要和加载状态。
- 记忆检索失败不阻断创作，SSE 返回 `memory` 降级状态，正文继续生成。
- `/api/ai/memory-extract` 从浏览器合并接口改为服务端内部处理入口，不再接受客户端直接写入记忆。

服务端提供：

- 记忆摘要与同步状态
- 按范围、分类和状态分页查询
- 单条创建、编辑、固定、停用、恢复和删除
- 清空全部记忆
- 变更历史查询
- 旧版本地记忆幂等导入
- 内部观察任务和相关记忆检索

所有用户接口都必须通过现有登录会话解析 `user_id`，禁止客户端指定目标用户 ID。

## 界面设计

### 对话记忆条

保留当前输入区上方的“AI 已记住”入口：

- 默认显示核心档案摘要和云端同步状态。
- 生成前后显示“本次加载了 N 条记忆”。
- 点击后展示“本次使用”和“长期档案”两个区域。
- 支持快速编辑、停用或删除单条记忆。
- 提取处理中显示“正在完善记忆”；失败显示可重试状态。
- 记忆条和展开区域必须内部滚动，不改变已经固定的输入区和页面滚动边界。

### 记忆中心

从记忆条和设置页面进入：

- 按全局、文案、身份定位、GEO 等范围分类。
- 展示当前有效、已停用和变更记录。
- 支持编辑、固定、停用、恢复、删除和清空全部。
- 展示为什么被记住、最后确认时间和最近使用模块。
- 提供账号总开关和模块开关。
- 对同步失败、离线缓存和待重试状态使用明确文案，不能把缓存显示为已同步。

## 错误处理与一致性

- 记忆写入和冲突替换在同一数据库事务中完成。
- 幂等键防止网络重试造成重复写入。
- 观察任务使用有限次数的指数退避；永久失败进入可诊断状态。
- 云端读取失败时可显示脱敏本地缓存，但必须标记为“缓存内容，尚未同步”，且不得用缓存直接覆盖云端。
- 用户编辑、停用、删除和清空成功后，所有后续检索立即遵循新状态。
- 多设备并发编辑使用 `revision` 乐观锁；冲突返回当前版本，由客户端刷新后重试。

## 安全与隐私

- 所有表和查询以 `user_id` 为首要隔离条件。
- 管理接口不返回其他用户的记忆内容；管理统计只允许聚合和脱敏数据。
- 来源摘要设置长度上限，不保留完整对话正文。
- API 错误和日志不得包含记忆正文、用户消息、密钥或敏感过滤命中内容。
- 删除和清空操作需要显式确认，并支持短期恢复；彻底清除不可恢复。

## 验收标准

### 自动化测试

- 同一账号跨设备读取相同记忆，不同账号严格隔离。
- 重复观察任务不会创建重复记忆。
- 相同表达增强权重，明确新表达替换旧值。
- 人工编辑不会被低置信自动提取覆盖。
- 敏感样本不会进入正文、来源摘要或日志。
- 提取失败可重试，不影响聊天且不扣用户创作积分。
- 模块只能读取全局和本模块记忆。
- 服务端忽略客户端伪造的 `memoryContext`。
- 检索数量、字符预算、优先级和状态过滤符合规则。
- 编辑、停用、恢复、删除、清空和乐观锁冲突均有接口测试。
- 旧版 localStorage 导入幂等且不会覆盖人工云端记忆。

### 真实 UAT

- 使用两个真实账号验证跨账号隔离。
- 使用两个客户端或设备验证跨设备同步。
- 验证新信息自动出现、重复信息增强、冲突信息替换和旧版本记录。
- 验证手动编辑、停用、恢复、删除和清空后下一次生成立即生效。
- 在 1920×900、1366×768 下验证记忆条、展开区域和记忆中心，不产生页面整体滚动。
- 断开云端服务时验证缓存和同步状态文案，不得显示虚假成功。

## 非目标

- 本阶段不实现聊天历史跨设备同步。
- 本阶段不引入向量数据库。
- 本阶段不保存AI回复为用户事实。
- 本阶段不保存临时任务、一次性素材要求或敏感信息。
- 本阶段不改变 GEO、视频等模块已有模型选择能力。
