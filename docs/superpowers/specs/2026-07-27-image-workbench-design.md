# 图片工作台设计

## 1. 背景与目标

现有“海报图创作”已经具备 RunningHub G-2 文生图、两张候选图、比例与横竖屏选择、任务轮询、计费和下载能力。本阶段将该单一页面升级为“图片工作台”，下设：

- 海报图创作
- 图片创作

两个分区共享 RunningHub 图片生成、任务状态、结果缓存和下载底座，但分别维护业务表单、提示词模板和参考图策略。页面继续保持普通业务工具定位，不注册业务助理。

本设计替代 `2026-07-26-runninghub-poster-creation-design.md` 中“页面仅服务海报”的产品边界；其中已经实现的比例、并发候选图和 RunningHub 客户端能力继续复用。

## 2. 用户入口与整体布局

### 导航

- 侧栏入口由“海报图创作”改名为“图片工作台”。
- 工作台首页快捷入口、全局搜索、面包屑和主视图枚举同步改名。
- 不保留第二个并列侧栏入口，避免图片能力分散。

### 页面

页面延续现有工作台 UI：

- 浅灰页面背景。
- 白色圆角内容卡片。
- 紫色为图片业务主色。
- 顶部使用紫色至玫红渐变 Hero。
- 桌面端采用左侧创作设置、右侧生成结果的双栏布局；窄屏上下堆叠。

Hero 标识调整为：

- 英文：`IMAGE STUDIO`
- 中文：`图片工作台`
- 说明：同一 RunningHub 图片引擎覆盖海报和通用图片创作。

Hero 下方设置两个胶囊式分区标签。切换分区时保留各自草稿和结果，不把一方表单值覆盖到另一方。

## 3. 方案选择

### 采用：共享工作台壳层 + 业务策略注册表

建立一个共享图片工作台壳层，统一：

- 分区切换。
- 比例与横竖屏。
- 清晰度。
- 参考图上传基础组件。
- 提交、轮询、错误状态和结果下载。
- RunningHub 文生图/图生图选择。

海报与图片创作通过策略配置提供：

- 表单字段。
- 提示词构建器。
- 模板清单。
- 参考图数量、角色和参考方式。
- 业务文案。
- 计费场景。

该结构允许后续增加电商主图、证件照等分区，而不需要复制任务管线。

### 不采用：两个完全独立页面

独立页面会重复比例选择、上传、轮询和结果画廊，也容易产生不一致的错误处理。

### 不采用：一个包含大量条件判断的组件

在原海报组件中直接堆叠 `mode === ...` 条件，短期改动较少，但表单、提示词和引用逻辑会快速耦合，难以独立测试。

## 4. 业务分区

### 4.1 海报图创作

#### 表单

- 海报用途。
- 主标题，必填。
- 辅助文案，可选。
- 海报模板。
- 视觉风格。
- 比例族与横竖方向。
- 清晰度。

#### 模板

- 品牌宣传。
- 活动促销。
- 新品发布。
- 知识海报。

模板只提供默认用途、视觉风格和提示词约束，不覆盖用户已经填写的标题与文案。

#### 参考图

最多两张，使用固定角色：

1. 商品/主体图：用于保持核心商品、人物或物体特征。
2. 风格参考图：用于参考配色、材质、光影和版式氛围。

两个槽位均可选。没有参考图时调用文生图；只要存在任意参考图就调用图生图。提交给 RunningHub 时按“商品/主体图、风格参考图”的顺序排列，并在提示词中明确图片顺序。

海报提示词要求：

- 中文标题清晰。
- 信息层级明确。
- 商业构图与合理留白。
- 不生成二维码、水印和虚构品牌标志。
- 有主体参考图时保持主体特征。
- 有风格参考图时只借鉴风格，不复制其中的文字与品牌。

### 4.2 图片创作

#### 表单

- 创作模板。
- 画面描述，必填。
- 补充要求，可选。
- 参考方式。
- 比例族与横竖方向。
- 清晰度。

#### 模板

- 电商主图。
- 人物写真。
- 场景设计。
- 社媒配图。
- 自由创作。

模板提供角色化系统提示词：

- 电商主图强调商品主体、商业光影和干净背景。
- 人物写真强调人物一致性、自然皮肤和摄影质感。
- 场景设计强调空间关系、材质和光线。
- 社媒配图强调视觉焦点、留白和移动端可读性。
- 自由创作只保留安全和画质约束。

#### 参考图

最多四张，用户可排序和删除。支持三种参考方式：

- 保持主体：优先保持人物、商品或物体特征，允许调整背景和构图。
- 参考风格：只参考色彩、材质、光影和视觉语言，不复制文字和标志。
- 综合重绘：综合参考主体和风格，允许较大幅度重构。

没有参考图时隐藏参考方式并调用文生图；存在参考图时调用图生图。参考方式转换成稳定的提示词前缀，不能由浏览器直接决定 RunningHub 端点。

## 5. 共享领域模型

### 模式

```ts
type ImageWorkbenchMode = "poster" | "image"
```

### 请求

```ts
type ImageWorkbenchGenerateRequest = {
  mode: ImageWorkbenchMode
  prompt: string
  aspect_ratio: ImageAspectRatio
  resolution: "1k" | "2k"
  count: 2
  reference_images: Array<{
    role: "subject" | "style" | "general"
    mime_type: "image/jpeg" | "image/png" | "image/webp"
    data_base64: string
  }>
  reference_mode?: "preserve_subject" | "style_only" | "remix"
}
```

服务端重新校验模式、比例、分辨率、数量、图片类型、单张大小和参考图数量，不能信任浏览器解析结果。

### 状态

共享状态返回：

- `task_id`
- `mode`
- `status`
- `image_urls`
- `warning`
- `error`
- `stage_label`
- `aspect_ratio`

只有至少一张图片已经下载到本地缓存后，任务才能标记为成功。RunningHub 返回成功但没有有效 URL 不算成功。

## 6. RunningHub 数据流

1. 浏览器按当前分区构建业务提示词。
2. Next.js 路由校验请求并按模式扣费。
3. FastAPI 创建本地图片任务并立即返回任务 ID。
4. 有参考图时，FastAPI 解码临时文件并上传 RunningHub；无参考图时跳过上传。
5. 无参考图调用 G-2 `text-to-image`。
6. 有参考图调用 G-2 `image-to-image`。
7. 两张候选图使用两个独立 RunningHub 任务并发生成。
8. 有效结果下载到共享图片缓存目录。
9. 前端轮询终态并显示一张或两张结果。
10. 临时参考图在任务结束后清理。

海报和图片创作使用同一个 `RunningHubClient`。图片 API 配置继续独立于云模型同步配置，不新增环境变量。

## 7. API 与兼容

新增通用接口：

- `POST /api/image-workbench/generate`
- `GET /api/image-workbench/status`

FastAPI 使用相同路径。

现有 `/api/poster/generate` 和 `/api/poster/status` 在迁移期保留为兼容适配器，内部转换为 `mode="poster"` 的共享请求；新前端只调用通用接口。兼容接口不新增功能，后续确认没有旧客户端使用后再删除。

## 8. 计费

两个业务分区使用独立云端场景：

- `poster_image`：20 积分/次。
- `image_creation`：20 积分/次。

一次扣费对应一次用户确认的生成操作，固定生成两张候选图。计费发生在请求通过 Next.js 参数校验后、FastAPI 创建任务前。

两个场景都必须加入：

- TypeScript 定价注册表。
- 云端 FastAPI `SCENE_COST_TABLE`。
- 云端部署版本。

余额不足显示“积分不足”；未知场景、云端不可用和其他扣费错误不能全部压缩为相同提示，至少区分“计费项目未配置”和“计费服务暂时不可用”。

## 9. 参考图安全与限制

- 接受 JPEG、PNG、WebP。
- 单张原始文件最大 10MB。
- 海报最多两张。
- 图片创作最多四张。
- 浏览器显示缩略图、文件名和删除按钮。
- 前端在上传前校验类型和大小；后端重复校验 base64 解码后的真实字节数。
- 图片只作为本次生成输入，不写入用户长期记忆。
- RunningHub 上传 URL 和本地临时路径不返回浏览器。

## 10. 状态与错误体验

工作台统一呈现：

- 空闲：显示当前分区的使用说明。
- 上传参考图：显示上传进度阶段。
- 生成：显示 RunningHub 候选图生成阶段。
- 部分成功：展示已成功结果并提示可重试。
- 失败：显示可理解错误和重新生成入口。
- 超时：停止前端轮询，但不把任务写成失败；用户可重新查询。

切换分区时取消该分区当前组件的前端轮询显示，但不取消已经提交的 RunningHub 任务。再次切回时恢复该分区保存的任务 ID 并继续查询。

## 11. 组件边界

建议结构：

```text
components/image-workbench/
  image-workbench.tsx
  workbench-mode-tabs.tsx
  poster-creation-panel.tsx
  image-creation-panel.tsx
  reference-image-uploader.tsx
  image-ratio-selector.tsx
  image-result-gallery.tsx

lib/image-workbench/
  types.ts
  strategies.ts
  poster-prompt.ts
  image-prompt.ts
  reference-images.ts
  api.ts
```

`image-workbench.tsx` 只负责编排分区草稿和任务状态；业务表单不直接调用 `fetch`；提示词构建器保持纯函数；参考图上传组件不包含业务提示词逻辑。

## 12. 验收标准

### 导航与 UI

- 侧栏、首页入口、搜索和面包屑统一显示“图片工作台”。
- 工作台提供“海报图创作”和“图片创作”两个分区。
- 两个分区切换后各自草稿和结果保持不变。
- 桌面与窄屏布局均可操作，没有固定比例裁切。

### 海报

- 无参考图时走 RunningHub 文生图。
- 商品/主体图或风格参考图存在时走图生图。
- 参考图角色顺序稳定。
- 海报模板、比例、方向和清晰度进入最终请求。

### 图片创作

- 支持五种模板和自由画面描述。
- 支持零至四张参考图。
- 三种参考方式进入最终提示词。
- 无参考图走文生图，有参考图走图生图。

### 计费与任务

- 海报调用 `poster_image`。
- 图片创作调用 `image_creation`。
- 未注册云端场景返回明确配置错误。
- 一次操作只扣一次费。
- 至少一张有效本地图片才算成功。

### 验证

- TypeScript 领域、提示词、路由和 UI 合同测试通过。
- Python RunningHub 客户端、参数校验、上传、并发生成和部分成功测试通过。
- `npx tsc --noEmit` 通过。
- 页面交互验证覆盖分区切换、参考图增删、横竖比例、生成状态和下载。
- 只有真实云端扣费和 RunningHub 返回图片后，才记录外部端到端验证成功。
