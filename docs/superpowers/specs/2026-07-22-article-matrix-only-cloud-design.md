# 深度文章矩阵唯一入口与云端模型设计

## 目标

深度优化文章只能从已生成的内容矩阵创建。文章页不再让用户选择 AI 引擎、平台爆款 Skill、创作模式或发布平台，避免文章配置与矩阵规划相互冲突。

## 页面设计

- 删除 AI 引擎选择器；显示不可交互的“云端智能调度”状态。
- 删除 A/B/C Skill 手动选择工具栏。页面加载矩阵项目后，展示只读摘要：目标优化策略、已自动加载的平台 Skill、企业知识库状态。
- 删除“自定义方向 / 内容矩阵”切换及自定义方向输入。
- 保留矩阵项目、发布日期和每格篇数选择。
- 删除发布平台选择；平台集合完全取自所选项目已生成的 `matrix.platforms`，无有效矩阵时禁止生成。

## 数据来源

- 服务端按 `projectId` 重新获取矩阵项目，不采信客户端的 `provider`、`modelSkillId`、`viralSkillIds`、`enterpriseSnapshot` 或 `platformIds`。
- 文章任务由所选日期与矩阵内全部有效平台交叉展开。
- A 层策略取矩阵项目 `modelSkillId`。
- 每篇文章的 B 层 Skill 通过该任务 `platformId` 映射对应 `viralSkillId`，不得混入其他平台 Skill。
- C 层知识库取矩阵项目保存的 `enterpriseSnapshot`。
- 单篇重试必须携带矩阵 `projectId`，服务端重新加载同一项目并恢复上述上下文。

## 云端模型

- 批量生成、自动修订、失败重试和 GEO 评分仅使用云端同步且 `source === "cloud"` 的文案模型候选。
- 候选按云端顺序尝试；网络错误、超时、非 2xx、空正文或评分 JSON 无效时自动切换备用渠道。
- 没有云端模型时返回 `CLOUD_MODEL_NOT_READY`；全部失败时返回 `CLOUD_MODEL_UNAVAILABLE`。
- 旧客户端即使继续发送 `provider` 也会被忽略。
- 保留现有 GEO 文章计费：仅在一次生成或修订获得有效模型正文后扣费，渠道切换不重复扣费。

## 兼容与错误处理

- 旧本地缓存的 `direction`、`platformIds` 和 `provider` 不再恢复到界面，也不进入请求。
- 旧文章仍可浏览、编辑、导出；旧的 direction 模式失败任务不再从自定义方向重建，提示用户回到内容矩阵重新创作。
- 矩阵项目不存在、尚未生成矩阵或所选日期无有效格子时，服务端返回明确错误且不扣费。
- 不改变文章字数、结构、违禁词检查、导出和编辑器能力。

## 验收标准

- 文章页不存在可点击模型选择、平台 Skill 选择、模式切换、自定义方向和发布平台选择。
- 切换矩阵项目后，平台数量和 Skill 摘要自动更新。
- 篡改请求中的 provider、平台或 Skill 不改变实际模型路由及文章上下文。
- 每篇文章只加载其目标平台对应的 B 层 Skill。
- 批量生成、重试、评分的首选云端渠道失败时测试确认会使用备用渠道。
- 聚焦测试、TypeScript 检查和生产构建通过。
