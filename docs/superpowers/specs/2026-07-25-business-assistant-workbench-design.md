# 功能型工作台与全局业务助理设计

- 日期：2026-07-25
- 状态：已批准
- 适用项目：`zhongtai-main`
- 实施方式：在现有 Next.js / FastAPI / Electron 架构内增量实现

## 1. 背景

现有工作台首页主要展示快捷创作卡片、智能体卡片和静态 AI 建议，缺少明确的大业务入口，也不能持续理解用户所处页面、业务目标和真实进度。用户需要的工作台不是任务看板，而是：

1. 清楚进入视频创作、GEO 创作、海报图创作、抖音截流和身份定位等大业务方向。
2. 使用可跨页面保持的专业助理，持续读取账号记忆、当前项目、页面步骤和真实任务状态。
3. 由助理帮助用户制定计划、解释下一步、预填低风险内容，并在受控边界内推动业务完成。

## 2. 已批准的产品决策

1. 首页采用“方案 A：业务入口 + 项目推进”。
2. 完整保留现有品牌欢迎 Banner，包括数字形象、欢迎语、营销获客定位、北京时间和日期。
3. Banner 下增加紧凑的“继续当前项目”区域。
4. 首页展示五个大业务方向：视频创作、GEO 创作、海报图创作、抖音截流、身份定位。
5. 首页不再展示小粒度文案模板、细分视频入口、静态 AI 建议或大面积智能体列表。
6. 全局助理使用一个悬浮入口，挂载在应用根层，切换页面不关闭、不丢失当前项目与对话状态。
7. 首版只实现“视频创作助理”和“GEO 助理”。
8. 身份定位没有独立助理，但作为两位助理统一复用的共享基础档案。
9. 海报图创作没有助理；首页入口进入独立的普通业务页面。
10. 抖音截流助理仅保留注册表扩展位，不允许调用，不展示成已上线能力。
11. 首版不实现业务总助理，不建立跨所有模块的总协调对话。
12. 助理可执行导航、打开项目、写入计划和预填草稿；扣积分、启动生成、发布和外部触达必须按现有规则确认或审批。

## 3. 目标与非目标

### 3.1 目标

- 让用户从首页一眼识别五个大业务方向。
- 让视频和 GEO 项目能够跨页面、跨刷新、跨设备恢复目标、阶段计划和关联产物。
- 让助理基于全局记忆、专业记忆、项目状态和页面上下文给出可执行指导。
- 让业务进度只由真实草稿、任务和产物推进，不由聊天措辞或页面跳转伪造。
- 在桌面宽屏和常见笔记本分辨率下保持原业务页面可操作。

### 3.2 非目标

- 不实现身份定位助理、海报助理、抖音截流助理或业务总助理。
- 不替换现有企业部门智能体中心。
- 不重写视频、GEO、账号记忆、积分或审批系统。
- 不让模型自主启动扣费任务或外部发布。
- 不把对话历史当作业务项目或真实进度。

## 4. 首页信息架构

首页从上到下为：

1. **品牌 Banner**：复用现有 `TopBanner`，内容和视觉主体保持不变。
2. **继续当前项目**：显示最近更新且未完成的视频或 GEO 项目；没有项目时显示“创建第一个项目”。
3. **五大业务入口**：
   - 视频创作：进入默认视频工作区。
   - GEO 创作：进入企业知识库工作区。
   - 海报图创作：进入无助理的海报生成工作区。
   - 抖音截流：显示明确的预留状态，不声称已上线。
   - 身份定位：进入现有身份定位工作区。
4. **最近业务项目**：最多展示近期两个视频/GEO项目，支持继续和查看全部。
5. **全局助理悬浮入口**：固定在右下角，角标只表达真实的待处理消息或计划更新。

首页移除现有 `DashboardQuickActions`、`DashboardAIInsights` 和智能体卡片列表。保留这些组件文件供其他页面或后续迁移使用，不在本阶段删除。

## 5. 助理范围

### 5.1 视频创作助理

复用企业智能体注册表中的 `video-production` 专业角色和视频生产 Skills。标准业务流程：

1. 明确目标、平台、受众和成片形式。
2. 复用身份定位，形成选题和脚本。
3. 检查形象、声音、素材、画幅和时长。
4. 在用户确认后启动生成。
5. 读取真实任务状态，等待成片。
6. 进行画面、音频、字幕、时长和封面质检。
7. 准备分发材料；发布继续走原审批边界。

### 5.2 GEO 助理

复用企业智能体注册表中的 `geo-growth` 专业角色和 GEO Skills。标准业务流程：

1. 检查企业主体、产品、人物、地点和官方联系方式。
2. 检查知识库资料和事实来源。
3. 规划查询簇与内容矩阵。
4. 生成文章。
5. 读取真实评分结果并提出优化。
6. 准备导出或分发，不承诺模型收录、引用或排名。

### 5.3 未上线能力

- `channel-interception` 作为抖音截流助理的保留 ID，只出现在内部能力注册表，不进入可选助理列表。
- 身份定位和海报图创作不注册助理。
- 在不支持的页面，悬浮入口可以继续打开既有视频/GEO对话，但必须明确“当前页面尚未接入上下文”。

## 6. 全局悬浮助理

### 6.1 挂载与持续性

`BusinessAssistantProvider` 和 `BusinessAssistantShell` 挂载在 `app/page.tsx` 的业务内容容器外侧，与 `TaskRuntimeProvider` 同级。切换 `activeView` 只更新页面上下文，不卸载助理。

状态分为：

- 收起：右下角可拖动悬浮球。
- 展开：桌面端右侧抽屉；移动端底部抽屉。
- 最小化：保留当前助理、项目和未发送输入。

桌面端展开时为主内容增加右侧空间，不遮挡表单关键操作；小屏使用覆盖式抽屉并可一键收起。

### 6.2 三个页签

- **对话**：当前页面摘要、助理建议、受控动作和输入框。
- **计划**：项目目标、阶段、步骤、依赖、状态和关联产物。
- **记忆**：本次实际使用的共享记忆与专业记忆；加载失败时明确降级状态。

### 6.3 助理切换

- 视频页面推荐视频助理，GEO 页面推荐 GEO 助理。
- 不在进行中的对话里静默切换角色。
- 用户可手动切换或固定助理。
- 进入未支持页面时保留原助理，不注入未经注册的页面上下文。

## 7. 页面上下文

各业务工作区通过 `AssistantPageContextBridge` 发布受约束摘要：

- `activeView`
- `module`：`video` 或 `geo`
- `workflow`
- `stepId` 与 `stepLabel`
- 当前草稿或项目 ID
- 必填字段完成状态
- 关联运行任务的 ID、状态、进度和阶段
- 可执行的低风险页面动作

页面上下文不得包含 API Key、Cookie、完整附件正文或不必要的个人信息。模型只能看见白名单字段和裁剪后的用户可见摘要。

## 8. 项目计划与真实进度

### 8.1 数据模型

`business_projects`：

- `id`
- `user_id`
- `kind`：`video` 或 `geo`
- `title`
- `goal`
- `status`：`active`、`paused`、`completed`、`archived`
- `current_stage`
- `assistant_id`
- `revision`
- `created_at`、`updated_at`

`business_project_steps`：

- `id`
- `project_id`
- `user_id`
- `stage`
- `title`
- `status`：`pending`、`active`、`blocked`、`completed`
- `order_index`
- `linked_view`
- `linked_task_id`
- `linked_artifact_json`
- `blocked_reason`
- `revision`
- `created_at`、`updated_at`

`business_assistant_messages`：

- `id`
- `project_id`
- `user_id`
- `assistant_id`
- `role`
- `content`
- `metadata_json`
- `created_at`

所有查询以 `user_id` 为隔离条件。项目和步骤更新使用 `revision` 乐观锁。

### 8.2 进度规则

- 页面跳转、点击按钮或模型声称完成不能改变步骤为 `completed`。
- 草稿型步骤可由真实保存事件完成。
- 生成型步骤只能由任务运行时终态和真实结果完成。
- GEO 评分步骤只能由有效评分结果完成。
- 失败任务将关联步骤设为 `blocked`，保留错误摘要和继续入口。
- 用户可以手动暂停、恢复或归档项目。

## 9. 记忆

复用现有账号级长期记忆系统：

- 两位助理都读取 `global` 与 `positioning` 记忆。
- 视频助理新增 `video` 范围。
- GEO 助理读取现有 `geo` 范围。
- 每次只检索当前任务相关记忆，并在“记忆”页签展示实际使用项。
- 记忆服务不可用时，对话可继续，但返回 `unavailable`，不得使用缓存假装已同步。
- 临时表单状态和一次性任务不写入长期记忆，只进入项目或页面上下文。

## 10. 助理请求与响应

客户端请求包含：

- `assistantId`
- `projectId`
- 用户消息
- 当前页面上下文版本
- 建议动作确认信息

服务端自行读取：

- 登录用户
- 项目与计划
- 相关记忆
- 助理系统合同和 Skills
- 云模型路由

响应包含：

- 助理文本
- 使用的记忆元数据
- 项目版本
- 结构化建议动作
- 计费与模型路由状态
- 警告

结构化动作第一版仅允许：

- `navigate`
- `open_project`
- `update_plan`
- `prefill_draft`
- `request_generation_confirmation`

任何未知动作、跨模块动作或参数不匹配动作都被拒绝。客户端不得提交模型 ID。

## 11. 海报图创作

首页海报入口进入独立的普通业务页面，不注册助理。首版复用现有 `/api/ai/ark-images` 与 `lib/ark-images-client.ts`，提供：

- 海报用途
- 核心文案
- 视觉风格
- 画幅
- 生成按钮
- 结果预览与下载

该页面不进入视频/GEO项目计划，不读取专业助理记忆。

## 12. 安全与审批

- 导航、打开项目、更新计划和本地预填属于低风险操作。
- 启动 AI 生成前显示积分成本、目标模块和关键参数，并要求用户确认。
- 发布、私信、外联和账号操作继续使用现有 T2 审批与真实发送验证。
- 助理不得伪造任务完成、平台成功、模型收录或业务效果。
- 页面上下文、记忆、项目和消息均按账号隔离。

## 13. 错误处理

- 记忆失败：显示“长期记忆未加载”，对话降级继续。
- 项目失败：保留聊天和输入，不显示进度，允许重试。
- 模型失败：不修改项目或步骤。
- 页面未接入：显示不支持当前页面上下文。
- 版本冲突：返回当前版本，客户端刷新后再应用。
- 重复生成：使用幂等键阻止重复扣费和重复提交。
- 助理扩展位：未启用的抖音截流助理返回 `ASSISTANT_NOT_AVAILABLE`。

## 14. 验收

### 14.1 自动化测试

- 首页保留 `TopBanner`，显示五个大业务入口，不再挂载旧快捷卡、静态建议和智能体列表。
- 助理注册表仅公开视频和 GEO；抖音截流不可调用。
- 助理 Shell 在 `activeView` 变化后不卸载。
- 视频和 GEO 页面只发布各自白名单上下文。
- 两位助理共享 `global`/`positioning`，专业记忆相互隔离。
- 项目、步骤和消息按用户隔离，乐观锁冲突返回 409。
- 只有真实事件能完成计划步骤。
- 未确认生成动作不能执行。
- 记忆、项目和模型失败不会伪造进度。
- 海报页面能调用现有生图 API 并显示错误。

### 14.2 真实 UAT

- 创建一个视频项目，跨页面、刷新和重启恢复计划。
- 视频助理读取身份定位并指导完成一次真实视频生成。
- 创建一个 GEO 项目，完成知识库、矩阵、文章和评分链路。
- GEO 助理读取真实评分并更新下一步。
- 在支持与不支持页面间切换，助理保持打开且不越权读取。
- 在 1920×900 和 1366×768 下验证抽屉不遮挡关键操作。
- 验证抖音截流助理无法调用；进入海报页面时全局悬浮入口仍存在，但不注册或自动选择海报助理。

## 15. 实施顺序

1. 项目计划合同与持久化。
2. 助理注册表、上下文桥和受控动作。
3. 视频/GEO助理服务端请求链。
4. 全局悬浮 Shell。
5. 视频/GEO页面接入。
6. 首页重构。
7. 海报图普通工作区。
8. 自动化测试与真实 UAT。
