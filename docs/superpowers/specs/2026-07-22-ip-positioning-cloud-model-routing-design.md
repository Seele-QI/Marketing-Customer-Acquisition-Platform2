# 身份定位云端模型路由设计

## 目标

身份定位不再向用户展示或接受模型选择。前端只提交业务资料，服务端仅使用云端同步的文案模型，并按云端 `priority` 顺序自动故障切换。

## 契约

- 身份定位向导不导入或渲染 `AiModelPicker`，提交载荷不包含 `modelId`。
- 本地身份定位会话不再持久化 `modelId`；读取旧会话时忽略遗留字段。
- 身份定位 API 不使用客户端 `modelId`。旧客户端即使继续提交该字段，也不能改变服务端路由。
- 服务端候选模型仅取 `listCopywritingProviderCandidates({ hasImages: false })` 中 `source === "cloud"` 的渠道。
- 调用顺序完全服从云端 `priority`；网络错误、超时、非成功响应、空正文或无效报告结构时继续尝试下一渠道。
- 未同步云端模型时返回 `503 / CLOUD_MODEL_NOT_READY`；全部云端渠道失败时返回 `502 / CLOUD_MODEL_UNAVAILABLE`。
- 成功响应继续记录实际成功渠道的模型名称，供成本与审计展示，不参与后续选路。
- 身份定位的积分扣费仍保持一次业务任务一次扣费，不因故障切换重复扣费。

## 数据流

1. 向导提交 `intake` 与 `files`。
2. API 规范化资料并读取云端模型候选列表。
3. 分析器按云端顺序逐一调用，校验每次返回的定位报告 JSON。
4. 首个有效报告结束调用并返回实际模型元数据；无有效报告时返回统一云端错误。

## 兼容与测试

- 保持 API 对旧请求体的宽容解析，但不读取旧 `modelId`。
- 静态契约测试验证 UI、会话和请求中不存在模型选择字段。
- 路由测试验证旧 `modelId` 不影响云端候选顺序、没有云端配置时拒绝本地回退、失败时切换下一云端渠道。
