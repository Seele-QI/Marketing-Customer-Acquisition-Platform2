# 企业知识库轻向导重构设计

日期：2026-07-22  
状态：用户已确认视觉方案、数据流与验收方案

## 目标

将现有“一屏长表单 + 上传区 + 生成区”重构为资料优先的四步轻向导。客户感受到清晰引导，但所有关键事实继续使用结构化字段，不采用轮次较长、数据不稳定的纯聊天采集。

设计必须满足：

- 不偏离现有 GEO 模块青蓝色、浅色卡片式视觉体系。
- 客户只投入最少必要精力，资料可自动提取，选填信息允许以后补充。
- 不改变现有企业 Skill 存储结构及内容矩阵、文章创作的 C 层知识库读取契约。
- 模型由云端下发并按既有备用渠道自动回退，不提供用户模型选择。
- 联系方式只要求联系人姓名和一种官方联系方式，普通内容不得主动引用。

## 方案选择

比较过三种方案：

1. 一屏纯表单：完成速度快，但信息密度高，客户容易产生工作量压力。
2. 分步引导式表单：一次只完成一个小任务，同时保持字段可靠和可校验。
3. 纯 AI 对话：更像顾问，但轮次长、退出率高，企业名称与联系方式等事实不适合自由回答。

采用方案 2。它借鉴 IP 打造板块的步骤感，不照搬聊天形态。

## 四步流程

### 第一步：导入企业资料

- 支持现有 Word、PDF、TXT、Markdown 上传规格和数量限制。
- 上传为推荐操作，但允许“暂不上传，手动填写”。
- 上传成功后自动解析文本，并调用企业信息预填接口。
- 页面明确显示文件状态：解析中、已提取、失败、可重试。

### 第二步：确认企业信息

- 必要字段仍为企业名称、所属行业、核心产品或服务。
- 有资料时展示云端模型提取的候选值及“来自资料”的来源提示。
- 无资料或预填失败时展示三个字段的简短表单。
- 客户修改后的值为最终确认值；重新上传资料不得静默覆盖已确认值。
- 品牌故事、客户类型、差异化优势等信息不新增为阻塞必填项。

### 第三步：官方联系方式

- 必填：联系人姓名、一个首选联系方式。
- 方式支持手机、微信、邮箱；备用联系方式选填。
- 沿用现有联系方式格式校验。
- 清楚告知引用边界：只有内容明确涉及联系、咨询、预约或购买时才可引用。

### 第四步：预览并生成

- 分组展示企业主体、核心业务、联系方式、引用边界和资料来源。
- 缺少选填信息不阻塞生成。
- 显示“云端智能调度，失败自动切换备用渠道”，不展示模型选择器。
- 生成按钮调用现有企业 Skill 生成链路。

## 页面布局

桌面端采用三栏结构：

- 左栏：四步导航与完成状态。
- 中栏：当前步骤的聚焦任务。
- 右栏：知识准备状态与引用边界提示。

窄屏降级为顶部可横向滚动的步骤条，右侧信息并入当前步骤下方。所有输入控件保留明确标签、键盘焦点、错误关联和加载状态。

## 组件边界

- `GeoKnowledgeBaseView`：页面壳与向导入口，不承载字段细节。
- `GeoKnowledgeWizard`：步骤、草稿、校验、导航和生成编排。
- `GeoKnowledgeStepNav`：步骤状态展示。
- `GeoKnowledgeSourceStep`：文件上传与预填触发。
- `GeoKnowledgeEntityStep`：结构化企业信息确认。
- `GeoKnowledgeContactStep`：最小联系方式采集。
- `GeoKnowledgeReviewStep`：生成前确认与提交。
- 现有 `GeoDocUploadPanel`、联系方式校验、企业 Skill 生成器优先复用或拆出无样式逻辑，不重复实现业务规则。

## 数据与接口

### 向导草稿

新增版本化浏览器草稿，保存：

- 当前步骤。
- 企业结构化字段及字段是否已人工确认。
- 已上传资料的可恢复引用信息。
- 预填状态和最近一次非敏感错误摘要。

草稿不改变已生成企业 Skill 的存储键。生成成功后可清理当前草稿，但已生成 Skill 继续由现有 store 管理。

### 企业信息预填

新增认证接口 `POST /api/geo/enterprise-skill/prefill`：

- 输入为现有文档解析结果，不接受客户端模型或 Skill 覆盖字段。
- 使用云端下发模型候选并按顺序回退。
- 输出采用严格结构化 schema，至少包含企业名称、行业、核心产品以及字段来源摘要。
- 无效 JSON、字段类型错误或全部渠道失败时返回稳定错误码。
- 预填失败不得阻塞客户转为手填。

### 最终生成

继续调用现有 `/api/geo/enterprise-skill/generate` 和 `geo-enterprise-skills-v1` 存储链路。提交时只使用客户确认后的结构化实体、官方联系方式与当前资料内容。

## 数据优先级

1. 客户已确认或编辑的字段。
2. 当前资料预填候选。
3. 空值。

资料重新解析不得覆盖优先级更高的数据。预填候选只能填充空白或尚未确认的字段。

## 异常与恢复

- 文档解析失败：保留成功文件与页面草稿，允许单文件移除或重试。
- 云端预填失败：展示简短说明并自动进入手填路径。
- 联系方式校验失败：定位到第三步并聚焦第一个错误字段。
- 最终生成失败：保留全部草稿和资料，按钮变为重试，不显示成功状态。
- 页面刷新或离开后返回：恢复步骤和已确认字段。
- 旧版页面历史数据：进入向导时进行兼容归一化，不要求客户重新填写已存在字段。

## 验收与测试

- 四步导航、返回、刷新恢复和草稿版本迁移。
- 上传成功、部分解析失败、无资料手填。
- 预填成功、严格 schema 校验、首选渠道失败后备用渠道成功、全部失败转手填。
- 人工确认值高于预填值，重新上传不静默覆盖。
- 联系方式最小必填、备用方式选填、错误定位和焦点。
- 最终生成继续兼容现有企业 Skill 数据结构、存储键、内容矩阵及文章创作读取链路。
- 生成中断和网络错误不丢草稿。
- 桌面端、窄屏、键盘和辅助技术基础可用性。
- TypeScript 检查、相关 Node/Python 测试和 Next.js 生产构建通过。

## 非目标

- 不改造企业知识库 Skill 的最终内容标准。
- 不新增面向客户的模型选择器。
- 不把企业知识采集改为开放式聊天。
- 不要求客户填写完整企业档案、品牌故事或营销策略。
- 不改变内容矩阵和文章创作消费企业知识库的公开契约。
